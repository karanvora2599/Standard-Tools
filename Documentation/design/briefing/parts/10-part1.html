PART I

Why it exists

An agent can describe a portfolio fluently and still never have computed a single number in it. This library exists so that every number it reports came from a function that can be read, tested and replayed.

01The problem: numbers nobody computed

A language model produces the most plausible continuation of its context. A volatility, a Sharpe ratio or a basis-point spread is just another plausible continuation, and nothing in the text separates a figure that was computed from one that was written because it looked right.

Handing the model a quant library does not fix this by itself. Libraries written for people return untyped frames, fill gaps with silent defaults and expose every function at once. A model given all of it picks tools it should never have seen, passes arguments that are quietly ignored, and joins a quarterly filing on the date it describes rather than the date it was published. Each mistake yields a number that looks fine.

Six ways a computed answer still goes wrong

Overfitted resultThe best of forty backtests is reported as if it were the only one.Deflated Sharpe, PBO, purged cross-validation and the reality check, each taking the trial count.

None of these is exotic. Each is ordinary code or an ordinary request that looks right, and the cost of each is a confident number with nothing behind it. The rest of this document is how the library makes each one either impossible or visible.

02The approach: the agent chooses, the library computes

The split of work is strict. The model decides which question to ask and which tool answers it; the library does every piece of arithmetic, with typed inputs, typed outputs, and a record of what it read.

Typed at both ends

Each tool is one input model and one result model, both JSON-serializable for function calling. An input the model cannot express is an input the agent cannot get wrong.

Scoped by runtime

A client is served one of twelve runtimes, not the whole surface. Scope is enforced at dispatch, so a tool an agent was never given is unroutable rather than merely unlikely.

Honest by default

Every Sharpe-reporting tool takes the risk-free rate it is measured against. In-sample figures are labelled in-sample. Options that did not help on an honest test stay opt-in.

Recorded and replayable

A call through dispatch() can write a decision record, hash-chained across calendar days, that sqt replay re-runs and sqt verify checks.

Errors are part of the interface

A refusal is written for the model that will read it. It says what was wrong, which value would be accepted, and, for a tool from another runtime, which runtime owns it. The fuzzing layer of the tests (section 15) holds every tool to that contract for any input: a named refusal or a valid result, never a stack trace.

The same code for people

Nothing here is agent-only. The same functions are importable from Python: indicators, metrics, backtests, optimizers and models, with the same validation. The agent surface is a typed layer over the library, not a separate implementation of it.
