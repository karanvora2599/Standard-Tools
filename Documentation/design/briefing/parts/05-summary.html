—Executive summary

Standard Quant Tools is a Python library for quantitative finance, built to be called by AI agents. Every tool takes one Pydantic model and returns one, so an agent gets structured data back, and errors that say what to fix. The CPU-bound paths run in an optional C++ extension behind the same API, with a pure-Python fallback when it is not built.

The problem

A language model produces the most plausible next number, not a computed one. A Sharpe ratio, a hedge ratio or a volatility figure written by a model reads exactly like one that was calculated, and in finance a wrong number is a position. A model that is handed a library meant for people also gets untyped returns, silent defaults and hundreds of functions it was never meant to call.

The approach

The agent chooses; the library computes. 266 tools sit in twelve runtimes, each a separate dispatch table, and a client is served one runtime rather than the whole surface. Inputs are validated, unknown arguments refused, bulk values passed between runtimes as typed sqt:// references, and a call through dispatch() can leave a hash-chained decision record that replays it.

What makes it different

  • Scope is enforced, not suggested. A tool outside a runtime is unroutable, and the refusal names the runtime that owns it.
  • Point-in-time by declaration. A source says when its facts became knowable, and a join that would use hindsight is refused rather than quietly allowed.
  • Tested against planted answers. Nine test layers, from known-answer correctness to mutation testing, each catching a class of defect the others cannot.
  • Negative results are kept. Ports that did not pay off, and rules that did not help on an honest test, are reported beside the ones that did.

Status, stated plainly

Version 0.1.0 under Apache 2.0, 595 commits since 15 February 2026, CI green on Python 3.10, 3.11 and 3.12. The C++ extension builds wherever a compiler is present and is optional everywhere: without it every tool runs its Python path and gives the same answer. Live vendor behaviour is established only with a live key, and the suite says which tests need one.

What this document is not

It is not investment advice and not a performance claim. A test can show a statistic is computed correctly; it cannot show that a strategy makes money. Where a figure comes from planted data, it says so.

Three things to remember

1 · The model is not trusted to compute

It chooses a tool and reads its result. Every number comes from a typed, deterministic function whose code is open.

2 · Every call can be reconstructed

A decision record holds the inputs, the content hashes of the data read and a hash of the output, so a call can be replayed and compared.

3 · It says what it cannot do

A refusal names what was wrong and what to change. An in-sample number is labelled in-sample, and an untested option is opt-in.
